`docs/` is an Open Knowledge Format v0.2 bundle.[^okf-spec] Every `.md` file except `index.md` and `log.md` is
a concept: YAML frontmatter with at least `type`, then a markdown body. All project knowledge lives here; the
README is the public landing page and points in.

# Layout

| Directory | Concept type | Written by |
|---|---|---|
| (root) | `Project`, `Reference` | hand |
| [decisions/](decisions/index.md) | `Decision` | hand |
| [methodology/](methodology/index.md) | `Methodology` | hand |

| [project/](project/index.md) | `Project Plan`, `Portfolio Text` | hand |

Also generated: every `index.md` (entry text from each concept's `title` and `description`; order and section
headings outside `tables/` are curated and kept) and `powerbi/validation_queries.sql` (from the computations).
Never edit generated files by hand.

# Frontmatter

* Always: `type`, `title`, a one-sentence `description` (it becomes the index entry), `tags`, `status`.
* Producer keys used here: `id` ([D01](decisions/D01-source-featureserver-layer-0.md), F1) on decisions and findings; `area` and `logged_at` on decisions;
  `dax_measures` on metrics and computations; `table_id`, `materialized`, `row_count` on tables.
* Every timestamp is ISO 8601 UTC with an offset, e.g. `2026-09-23T12:41:15Z`.

# Provenance and trust

* `generated: { by, at }` records who wrote the content and its last meaningful change. Actors:
  `claude-code/claude-opus-5-5` (written by Claude Code), `build_knowledge/1` (generated by
  `scripts/build_knowledge.py`), `human:jpbranson` (the project owner).
* `sources` lists what a concept derives from. Cite a specific claim with a footnote whose label is a source
  `id`, e.g. `[^service-recurrence]`.
* `verified`: no concept is verified yet, so every concept is in the *unverified* trust tier. After checking a
  concept against its sources, add `verified: { by: human:jpbranson, at: <now> }` (or append to the list).
  A process that re-checks content uses a `process:` actor.
* `stale_after`: concepts that quote figures from the 2026-09-23 extract expire on 2026-12-23. To renew one,
  re-run the relevant [computations](computations/index.md) or mart queries, update the figures, then move
  `stale_after` forward and update `generated`.
* `status`: `draft`, `stable` or `deprecated`. Deprecate rather than delete a concept that others link to.

# Links

Use relative links (`../decisions/D22-primary-recurrence-definition.md`), not bundle-absolute `/…` links, so
links also work when the repository is browsed on GitHub. Refer to a decision by its ID and link it.

# Changing knowledge

* **A new decision**: take the next ID, create `decisions/D33-<slug>.md` with the same frontmatter shape, and
  write the body as **Decision.** / **Evidence.** / **Alternatives.** / **Consequence.** paragraphs.
* **Column or model descriptions**: edit `dbt/models/**/_*.yml`, then run the pipeline (or `dbt docs generate`
  followed by `scripts/build_knowledge.py`).
* **Sanctioned SQL**: edit the fenced block in a computation; `validation_queries.sql` follows on the next build.
* **Anything notable**: add a dated entry, newest first, to the [log](log.md).

# Commands

```bash
uv run python scripts/build_knowledge.py          # regenerate tables/, index.md files and the validation SQL
uv run python scripts/build_knowledge.py --check  # conformance, broken links, stale concepts, generated drift
```

`--check` exits non-zero on errors (missing `type`, malformed timestamps or actors, broken links, footnotes
without a source, out-of-date generated files) and warns on stale concepts.
